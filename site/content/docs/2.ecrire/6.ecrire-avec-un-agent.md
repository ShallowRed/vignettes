---
title: Écrire avec un agent
description: Donner à un agent de code les règles du format Vignettes, lui faire écrire une présentation dans le dépôt de votre produit, puis l'importer dans le studio.
---

Un agent de code écrit une présentation Vignettes depuis le dépôt de votre produit, où il lit le code, la documentation et les stories. Il écrit un fichier `.md`, que vous importez dans le studio.

La skill `writing-decks` contient, au format ouvert [Agent Skills](https://agentskills.io), les règles du format (l'en-tête, le découpage, les annotations, les composants et les stories Storybook) et les règles d'écriture : le plan selon l'objectif de la présentation, les titres et le texte des diapositives. Claude Code, Codex, GitHub Copilot, Cursor et les autres agents qui lisent ce format la chargent quand une demande nomme une présentation Vignettes.

## Installer la skill

La skill est publiée dans le dépôt [`ShallowRed/vignettes`](https://github.com/ShallowRed/vignettes), avec la skill `writing-themes` du plugin `vignettes-themes` ([Le thème de votre équipe](/docs/themes/theme-de-votre-equipe)).

Dans Claude Code, le dépôt est une marketplace de plugins. Dans une session :

```text
/plugin marketplace add ShallowRed/vignettes
/plugin install vignettes-decks@vignettes
```

Choisissez « Install for you (user scope) » pour l'utiliser dans tous vos projets. La commande `/vignettes-decks:writing-decks` apparaît ensuite dans la liste ouverte par `/`. Sur un ordinateur sans clé SSH pour GitHub, lancez Claude Code avec la variable `CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1`.

`/plugin marketplace update vignettes` installe la dernière version de la skill. Pour que Claude Code la mette à jour seul, activez la mise à jour automatique de la marketplace `vignettes` dans `/plugin`, onglet Marketplaces.

Pour les autres agents, la commande [`gh skill install`](https://cli.github.com/manual/gh_skill_install) de GitHub CLI, en préversion, place la skill dans le dossier que lit votre agent, nommé par `--agent` : `codex`, `github-copilot`, `cursor`, `gemini-cli`, ou un autre de la liste de `gh skill install --help`.

```bash
gh skill install ShallowRed/vignettes writing-decks --agent codex --scope user
```

Avec `--scope user`, la skill vaut pour tous vos projets ; avec `--scope project`, elle est installée dans le dépôt courant, et votre équipe la reçoit avec le dépôt. `gh skill update` installe la dernière version.

## Faire écrire la présentation

Ouvrez votre agent dans le dépôt de votre produit et demandez la présentation en nommant Vignettes :

```text
Écris une présentation Vignettes de six diapositives pour la revue de sprint, dans docs/presentations/revue-de-sprint.md.
```

Pour être sûr que l'agent charge la skill, demandez-lui d'utiliser la skill `writing-decks`, ou, dans Claude Code, commencez la demande par `/vignettes-decks:writing-decks`. Pour des écrans de votre Storybook, donnez-lui l'adresse du Storybook et le nom des composants ([Intégrer une story](/docs/ecrire/story-storybook)).

## Importer le fichier

Dans le catalogue, cliquez sur « Nouvelle présentation », choisissez le point de départ « Fichier Markdown », puis déposez le fichier. Le titre et le thème viennent de l'en-tête du fichier. Si l'en-tête n'a pas de clé `title`, saisissez le titre dans le formulaire : il est ajouté à l'en-tête. Si une clé a une valeur refusée, le message nomme la clé : corrigez le fichier, puis choisissez-le de nouveau.

La présentation créée est privée, et indépendante du fichier. Relisez-la dans l'aperçu, puis [publiez-la](/docs/demarrer/premiere-presentation#publier-et-partager).

## Faire modifier une présentation

1. [Téléchargez son texte](/docs/ecrire/presenter#télécharger-le-texte) et placez le fichier dans votre projet.
2. Demandez la modification à l'agent.
3. Dans l'éditeur, remplacez tout le texte par celui du fichier modifié, puis publiez. La version précédente reste dans l'[historique](/docs/studio/versions-et-brouillon#lhistorique).

Pour garder la présentation d'origine, importez le fichier modifié comme une nouvelle présentation.
